# GaggiMate+

Native iOS client for the [GaggiMate](https://github.com/jniebuhr/gaggimate) espresso machine controller, an ESP32 board that exposes a local WebSocket API. Display name "GaggiMate+" (read "GaggiMate Plus"); code and repo name `GaggiMatePlus`.

## Stack

- iOS 18+, SwiftUI, Swift 6 with strict concurrency, Swift Testing.
- Bundle ID `dev.niklashein.gaggimateplus`.
- The Xcode workspace is generated by Tuist from `Project.swift`; the Tuist version is pinned in `mise.toml`. The `.xcodeproj` and `.xcworkspace` are gitignored; run `tuist generate` after changing `Project.swift` or adding files.

## Modules

Every module is a static framework defined in `Project.swift`, with sources in `<Module>/Sources` and Swift Testing tests in `<Module>/Tests`. The `GaggiMatePlus` scheme runs all tests. Every direct dependency:

```text
GaggiMatePlus (app) ──> UI / Networking / DesignSystem / Models
UI                  ──> DesignSystem / Models
Networking          ──> Models
DesignSystem        ──> (nothing)
Models              ──> (nothing)
ModelsTests         ──> Models
NetworkingTests     ──> Networking / Models
```

- `App/`: the app target and composition root. It creates the Networking client, feeds its events into the store, and hands the store and commands to the UI through the environment. For now it has only the entry point and `RootView`.
- `Models`: Codable message types, machine state (including the partial `evt:status` merge), the `@Observable` store, and the command protocol that Networking implements.
- `Networking`: the WebSocket client.
- `UI`: SwiftUI screens. It never imports Networking; previews use fakes.
- `DesignSystem`: colours, typography and reusable styles.

```sh
mise install

```

## Branches and releases

- `main` is protected: changes land only through pull requests, and CI (`Test`) must pass. Pull requests from contributors need approval from the code owner.
- Releases are cut by pushing a `v*` tag (for example `v1.0.0`) on a commit on `main`. The release workflow creates the GitHub release with generated notes.

## GaggiMate WebSocket API

- Connect to `ws://<host>/ws`. No auth.
- JSON messages, typed by the `tp` field: `req:*` (client requests), `res:*` (responses), `evt:*` (pushed events).
- Requests and responses are correlated by `rid`.
- `evt:status` is PARTIAL:
  - Fast telemetry every 500 ms: `ct`, `tt`, `pr`, `pt`, `fl`.
  - Slow state is sent on change or at least every 10 s, and in full on connect.
  - Merge each frame onto the last known state: an absent key means keep the previous value, `null` means clear it.
- Spec source: <https://raw.githubusercontent.com/jniebuhr/gaggimate/master/docs/websocket-api.yaml>. Link it, don't vendor it: upstream is CC BY-NC-SA, this repo is MIT.

## Conventions

- The socket lives in an `actor` (Networking).
- UI state lives in an `@Observable` store (Models).
- Request/response uses async/await, keyed by `rid`.
- Reconnect with backoff when the connection drops.
